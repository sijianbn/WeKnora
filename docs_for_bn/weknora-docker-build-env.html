WeKnora Docker 编译环境

在任意装有 Docker 的电脑上，为 WeKnora（Go 后端 + Vue 前端）提供一套与 CI 一致的 Linux 编译/测试环境，一次预热后增量构建只需秒级。本页内容自成一体，不依赖仓库内任何文件，可整体拷走。

为什么需要它

Windows 本机直接装 Go 也编不过 WeKnora 后端，原因是三条 cgo 依赖链：

依赖被谁引用Windows 上的表现
pg_query_go/v6internal/utils（SQL 注入检测）API 全部在 //go:build cgo 后面，无 gcc 时 undefined: pg_query.Parse
sqlite-vec-go-bindingsinternal/container（SQLite 向量）缺 sqlite3.h，build constraints exclude all Go files
duckdb-go-bindingsinternal/container（桌面端）同上，Windows 绑定缺失

几乎全部业务包都间接依赖 internal/utils，所以在 Windows 上连单元测试都无法编译。装 mingw + 逐个补头文件可以绕（本机实测过），但脆、慢、且与 CI 环境不一致。Docker 方案一次搞定：

  • ✔ 一致 与 CI 同为 Linux + go 1.26 + gcc，测试结果可信
  • ✔ 增量 模块缓存 + 编译缓存落在两个命名卷里，改一个包只重编那一个包
  • ✔ 零污染 不在本机装 Go/gcc，不写注册表，删掉镜像与卷即彻底卸载

组成一览

组件名字说明
构建镜像weknora-go-builder:latestgolang:1.26 + build-essential + libsqlite3-dev（apt 走阿里源），内置 GOPROXY=goproxy.cn
模块缓存卷weknora-gomod-cache → /go/pkg/modGo 依赖包，warmup 一次填满

入口脚本docker-go.sh把任意 go 子命令放进容器执行；处理 Windows 路径转换等脏活

前置条件（新电脑）

清单
① Docker Desktop 已安装并运行（docker info 有输出）
② 已 clone WeKnora 仓库（建议 git clone --config core.autocrlf=false，原因见踩坑 · CRLF）
③ 网络二选一：代理可用（能拉 docker.io），或直连国内镜像源（下文给了命令）

① 拉取 golang 基础镜像

代理正常时直接拉；失败就用国内 registry 直连再改标签（两步等价）：

# 方式 A：代理正常
docker pull golang:1.26

# 方式 B：代理挂了 / 直连慢
docker pull docker.m.daocloud.io/library/golang:1.26
docker tag  docker.m.daocloud.io/library/golang:1.26 golang:1.26

② 构建 builder 镜像

在任意空目录创建 Dockerfile.go-builder（完整内容在附录），然后：

docker build -t weknora-go-builder:latest -f Dockerfile.go-builder .

构建耗时约 1–3 分钟（apt 走阿里源）。验证：

docker run --rm weknora-go-builder:latest sh -c "go version && gcc --version | head -1"

③ 保存 docker-go.sh

把附录中的脚本存为仓库根目录的 docs_for_bn/docker-go.sh（或任意位置，脚本会自动定位仓库根）。脚本做了三件脏活：

  • 路径转换：Git Bash 的 pwd -W 给出 C:/... 形式 + MSYS_NO_PATHCONV=1 阻止 Docker 参数被二次转换（这是最大的坑，见踩坑）
  • 挂载两卷：模块缓存 + 编译缓存
  • warmup 子命令：一次性填满两个缓存卷

④ 预热缓存（warmup，只需一次）

顺序很重要：如果这台电脑还没装前端依赖，先 cd frontend && npm install 再 warmup。warmup 里的 go build ./... 会遍历目录树，与 npm 同时跑会撞上 node_modules 中瞬时消失的目录而报错（pattern ./...: open frontend/node_modules/fsevents）。
cd <仓库根>
sh docs_for_bn/docker-go.sh warmup
# 首次 5–15 分钟（下载全部 Go 模块 + 全量编译）
# 看到 WARMUP-DONE 即成功；之后全量构建只要几秒

日常使用

场景命令
全量编译sh docs_for_bn/docker-go.sh build ./...
编译指定包sh docs_for_bn/docker-go.sh build ./internal/application/service/
跑某包测试sh docs_for_bn/docker-go.sh test ./internal/application/service/ -count=1
只跑匹配的测试sh docs_for_bn/docker-go.sh test ./internal/... -run TestExtensionSupport -v -count=1
静态检查sh docs_for_bn/docker-go.sh vet ./internal/...
刷新依赖后重预热sh docs_for_bn/docker-go.sh warmup

前端类型检查在宿主机跑即可（需 Node 22+，frontend/ 下 npm install 后 npm run type-check），不依赖本环境。

缓存机制

两个命名卷
weknora-gomod-cache（/go/pkg/mod）与 weknora-gobuild-cache（/root/.cache/go-build）由 Docker 持久化，容器销毁不丢。依赖大版本升级或想彻底重来时清理：
docker volume rm weknora-gomod-cache weknora-gobuild-cache 然后重新 warmup。

踩坑实录（按痛度排序）

1. Git Bash 路径转换把 -w /src 变成 C:/Program Files/Git/src

症状 the working directory 'C:/Program Files/Git/src' is invalid 或挂载路径前被拼上仓库路径。
解法 脚本内已内置 export MSYS_NO_PATHCONV=1；若手写 docker 命令，记得带上，并用 C:/... 正斜杠形式的挂载路径。

2. Docker Desktop 走系统代理，代理没开 = 全部拉取失败

症状 connecting to 127.0.0.1:7890: connection refused / EOF（Docker Desktop 把系统代理硬路由进 daemon）。
解法 ① 打开你的代理客户端（7890 端口）；或 ② 绕开 docker.io：docker pull docker.m.daocloud.io/library/golang:1.26 再改标签。镜像构建的 apt 已固定走阿里源，不受代理影响。

3. warmup 与 npm install 竞争

症状 pattern ./...: open frontend/node_modules/fsevents: no such file or directory。
解法 先 npm install 后 warmup（见步骤④的警告框）。

4. CRLF 检出导致 TestDeploymentCapabilityKeysMatchFrontend 误报

症状 该测试在容器内报 backend keys vs frontend keys 不一致，前端 keys 每个都拖着 ', 尾巴。
根因 core.autocrlf=true 检出时把 frontend/src/config/deploymentCapabilities.ts 变成 CRLF，测试的 trim 顺序处理不了 \r。容器挂载的是宿主机工作区，所以容器内同样中招。
解法 clone 时用 git clone --config core.autocrlf=false；已有仓库可忽略此误报（CI 的 LF 检出不受影响），或 git config core.autocrlf false && git rm --cached -r . && git reset --hard 重检出（注意会重写工作区）。

5. 容器内 TestSkillPythonPackageRecoveryInstallsWithoutPip 失败

症状 No module named ensurepip。golang 镜像自带的最小 python 没有 ensurepip。
解法 属已知误报，与代码无关；要消除可在镜像里加 python3-venv（apt），一般没必要。

6. 全量测试中仅这 2 个失败 ⇒ 可以放心

本环境全量 go test ./... 的基线：75 包 ok，仅上述 #4、#5 两处环境性失败。新改动只要不增加除此之外的失败即为干净。

Dockerfile.go-builder

# WeKnora Go 构建环境：golang:1.26 + 项目所需编译依赖（build-essential、libsqlite3-dev）。
# 模块缓存与构建缓存通过命名卷挂载（weknora-gomod-cache / weknora-gobuild-cache），
# 一次预热后，后续构建只编译改动的包。
FROM golang:1.26
ENV GOPROXY=https://goproxy.cn,direct
RUN sed -i 's|deb.debian.org|mirrors.aliyun.com|g' /etc/apt/sources.list.d/debian.sources 2>/dev/null || true \
 && apt-get update \
 && apt-get install -y --no-install-recommends build-essential libsqlite3-dev \
 && rm -rf /var/lib/apt/lists/*
WORKDIR /src

docker-go.sh

#!/bin/sh
# WeKnora Go 构建环境（Windows/Git Bash 用法：sh docker-go.sh <go 命令...>）
#
# 镜像:   weknora-go-builder —— golang:1.26 + build-essential + libsqlite3-dev
# 卷:     weknora-gomod-cache  → /go/pkg/mod        （Go 模块缓存，一次性预热）
#         weknora-gobuild-cache → /root/.cache/go-build （编译缓存，增量构建）
#
# 用法示例:
#   sh docs_for_bn/docker-go.sh build ./...
#   sh docs_for_bn/docker-go.sh test ./internal/application/service/ -count=1
#   sh docs_for_bn/docker-go.sh vet ./internal/...
#
# 首次使用前请先预热缓存（只需一次）:
#   sh docs_for_bn/docker-go.sh warmup

set -e

# Git Bash 的 pwd -W 直接给出 "C:/bn/gwz/WeKnora"（Docker 可用的正斜杠 Windows 路径）；
# 其他环境回退 pwd，若是 "/c/..." 形式则转成 "C:/..."。
REPO_DIR="$(cd "$(dirname "$0")/.." && pwd -W 2>/dev/null || true)"
if [ -z "$REPO_DIR" ]; then
  REPO_DIR="$(cd "$(dirname "$0")/.." && pwd)"
  case "$REPO_DIR" in
    /[a-z]/*) REPO_DIR="$(echo "$REPO_DIR" | sed 's|^/\([a-zA-Z]\)/|\U\1:/|')" ;;
  esac
fi

# Git Bash 会把 /src 转换成 Windows 路径，禁掉
case "$(uname -s)" in
  MINGW*|MSYS*|CYGWIN*) export MSYS_NO_PATHCONV=1 ;;
esac

if [ "$1" = "warmup" ]; then
  shift
  exec docker run --rm \
    -v "$REPO_DIR:/src" \
    -v weknora-gomod-cache:/go/pkg/mod \
    -v weknora-gobuild-cache:/root/.cache/go-build \
    -w /src \
    weknora-go-builder:latest sh -c "go mod download && go build ./... && echo WARMUP-DONE"
fi

exec docker run --rm \
  -v "$REPO_DIR:/src" \
  -v weknora-gomod-cache:/go/pkg/mod \
  -v weknora-gobuild-cache:/root/.cache/go-build \
  -w /src \
  weknora-go-builder:latest go "$@"
